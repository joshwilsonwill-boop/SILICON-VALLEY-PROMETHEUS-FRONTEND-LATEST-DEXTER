# DARTH VADER COMMUNIQUE

Contract between the **Prometheus front end (FE)** and the **animation/processing back end (BE)**.
Purpose: when a user drops a video into Prometheus, the FE uploads it and hands the BE a job.
This document is the single source of truth for **what the FE sends, what the BE must accept,
and how progress and results flow back.** Version: `1.0`

---

## 0. Ground rules (non-negotiable)

1. **Every job carries a prompt.** A job without a prompt is rejected with `400 PROMPT_REQUIRED`.
   There is no "generic animation" fallback. Silence is not consent.
2. **Prompt sources**, in priority order:
   - `user` — typed by the user (typical case).
   - `assistant` — generated by the AI assistant *and confirmed* by the user (e.g. the chat
     proposes animation specs; user approves). The confirmed text is what ships in the job.
   The job record must persist the final prompt text and its origin so the BE can always audit it.
3. **The BE never invents creative direction.** If the FE hands a prompt, the BE executes it.
   If parameters conflict, reject with a machine-readable error — do not guess.
4. **Everything the BE needs arrives in one envelope.** The BE should not have to scrape FE state.

## 1. What already exists (do not redesign)

| Piece | Where | Shape |
|---|---|---|
| Video upload (FE → Cloudflare R2) | `lib/r2/multipart-client.ts` | multipart, 50 MB parts, 10 GB cap, `storageProvider: 'r2'` |
| Asset registration | `POST /api/projects/{projectId}/assets` | registers the R2 object as the project source asset |
| Job queue | table `public.durable_jobs` + `POST /api/jobs/create` | see §2 |
| Job status polling | `GET /api/jobs/{id}/status` | `{ status, progress, ... }` |
| Progress | `durable_jobs.progress` | integer `0–100`, enforced by DB check |
| Realtime | `20260522000001_enable_realtime` migration | realtime enabled; BE may also push updates |
| Job types | enum `job_type` | `render`, `scene_detection`, `export`, `video_analysis`, `audio_processing`, `ai_enhancement` |
| Job statuses | enum `job_status` | `pending`, `processing`, `completed`, `failed` |

Today's `CreateJobRequest` is minimal: `{ projectId, type, metadata? }`. The animation contract
lives **inside `metadata`** (stored to `durable_jobs.result_metadata`), so the table/RLS/realtime
plumbing needs **no schema change** — only a wider enum value if new job types are added (see §6).

## 2. The Job Envelope (FE → BE)

Created by `POST /api/jobs/create`, then dispatched to the BE by whatever worker owns the queue row.

```jsonc
{
  "projectId": "uuid",                 // required — owning project
  "type": "ai_enhancement",            // job_type enum; animation jobs use this (see §6)
  "metadata": {
    "schema": "prometheus.anim.job/1", // required — lets BE reject unknown versions
    "prompt": {
      "text": "Cinematic 3s chrome logo resolve over the interview intro, slow dolly-in, teal rim light, film-grain tails.",
      "source": "user",                // "user" | "assistant"
      "locale": "en"
    },
    "assets": [
      {
        "role": "source",              // "source" | "reference" | "audio_bed"
        "assetId": "uuid",             // from /api/projects/{id}/assets
        "storage": "r2",
        "contentType": "video/mp4",
        "durationSec": 142.6,          // optional but recommended
        "width": 1920, "height": 1080  // optional
      }
    ],
    "preferences": {                   // the "extra package": animation preferences
      "jobKind": "longform_to_short",  // see §3
      "motionStyle": "cinematic",      // free preference, BE may ignore unknown keys
      "pacing": "slow",                // "slow" | "moderate" | "fast"
      "aspectRatio": "9:16",
      "clipLengthSec": 12,             // target for shorts
      "effects": ["vignette", "film_grain"],
      "brand": { "logoAssetId": "uuid-or-null", "palette": ["#0B0B0D", "#E8E4DA"] }
    },
    "idempotencyKey": "uuid-v4"        // required — safe retries
  }
}
```

**Validation the FE applies before sending** (BE must re-validate):
- `prompt.text` non-empty after trim, ≤ 2000 chars.
- `prompt.source ∈ {user, assistant}`.
- `assets[0].role = "source"` exists and belongs to `projectId`.
- `preferences.jobKind` from the controlled list in §3.
- `idempotencyKey` present (FE generates one per user action, reuses it on retry).

## 3. `preferences.jobKind` — controlled vocabulary

| `jobKind` | Meaning | Notes for BE |
|---|---|---|
| `longform_to_short` | Convert long-form content into short-form clip(s) | FE passes `clipLengthSec`; BE picks segments, applies prompt |
| `logo_sting` | Animated logo ident over/around footage | uses `preferences.brand.logoAssetId` |
| `motion_overlay` | Motion graphics pass over the existing cut | respects `effects[]` |
| `style_transfer` | Restyle footage according to prompt | highest compute; may be credit-gated |

Unknown `jobKind` → `400 UNKNOWN_JOB_KIND`.

## 4. Flow

```
User drops video
  → FE: R2 multipart upload                 (lib/r2/multipart-client.ts)
  → FE: register asset                      POST /api/projects/{id}/assets
  → FE: create job (envelope above)         POST /api/jobs/create
  → BE worker: row pending → processing, progress 0→100
        updates via POST /api/jobs/update (status, progress, errorMessage)
  → FE: reflects progress                   GET /api/jobs/{id}/status  (poll 2s while active)
                                            + realtime channel if enabled
  → BE: completed → writes outputs into result_metadata.outputs[]
  → FE: renders outputs (clips/previews), job done
```

**Progress contract** (`progress` is 0–100, monotonic while `processing`):
- `0–10` ingest/probe, `10–60` main compute, `60–90` render/encode, `90–100` finalize/upload outputs.
- FE shows the number verbatim plus a stage label from `metadata.stage` if the BE provides it.
- Stalls > 60 s at one value while `processing` → FE offers "retry / cancel" (no auto-retry).

## 5. Results and errors

`result_metadata.outputs[]` on completion:

```jsonc
{ "outputs": [
  { "role": "short_clip", "storage": "r2", "assetId": "uuid",
    "durationSec": 12.1, "width": 1080, "height": 1920, "thumbnailAssetId": "uuid" }
] }
```

Failures: `status = "failed"` + `error_message` populated with a stable code:

| Code | Meaning | FE behavior |
|---|---|---|
| `PROMPT_REQUIRED` | no/empty prompt | reopen prompt UI pre-filled |
| `SOURCE_UNREADABLE` | R2 object missing/corrupt | offer re-upload (asset id preserved) |
| `UNSUPPORTED_CODEC` | container/codec unsupported | tell user accepted formats |
| `CREDITS_EXHAUSTED` | billing gate | routing to billing flow |
| `BE_INTERNAL` | everything else | show retry with same idempotencyKey |

Idempotency: same `idempotencyKey` + same `projectId` + same `type` → return the existing job row,
never double-run.

## 6. Requests to the back end (please confirm or counter-propose)

1. **New job type**: add `'animation'` (or confirm we keep using `'ai_enhancement'`) to the
   `job_type` enum so animation jobs are queryable separately from credit-charged enhancements.
2. **Stage label**: echo a short `metadata.stage` string on updates (powers the FE progress caption).
3. **Cancellation**: is `POST /api/jobs/update` with `status:"failed", errorMessage:"CANCELLED_BY_USER"`
   the accepted cancel path, or do you want a dedicated endpoint?
4. **Outputs**: confirm you can register outputs as assets (so FE preview uses the existing
   `/api/projects/{id}/assets` read path) rather than returning raw URLs.
5. **Media envelope**: confirm accepted containers/codecs/resolution caps for `source` assets
   (FE will pre-validate to match).
6. **Realtime**: is the `durable_jobs` channel broadcast, or does the worker only write rows
   (FE polls)? FE supports both; pick one as canonical.

Open FE-side item (not blocking): studio uploads now also write IndexedDB so sources survive
navigation locally; BE can assume `sourceAssetId` on the project is authoritative.
